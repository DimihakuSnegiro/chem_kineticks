# CHEMAR на C++17

CHEMAR — программа для расчёта неравновесной химической кинетики идеальной газовой смеси. Она вычисляет изменение химического состава, температуры, давления и других термодинамических параметров во времени или вдоль потока.

Программа:

- напрямую читает химический механизм и начальные условия из трёх JSON-файлов;
- поддерживает произвольные названия веществ и химических элементов;
- проверяет атомный и массовый баланс реакций;
- рассчитывает прямые и обратные скорости реакций;
- поддерживает пять режимов термодинамического или газодинамического расчёта;
- решает жёсткую систему уравнений адаптивным неявным методом SDIRK второго порядка;
- сохраняет результаты в CSV и JSON;
- может открывать отдельные графики температуры, давления и состава смеси.

Весь собственный код C++ находится в одном файле `main.cpp`. Старые файлы CHEMAR `DHIM.h2`, `bufermm.h2` и `buferk1` C++-программа не читает. Они нужны только необязательному Python-конвертеру.

## 1. Быстрый запуск

Откройте PowerShell в каталоге проекта:

```powershell
cd C:\chem_kinetics
```

Запустите уже собранную программу:

```powershell
.\build\chemar.exe
```

После успешного расчёта появятся:

```text
output\results.csv
output\results.json
```

Чтобы сразу выполнить расчёт и открыть графики:

```powershell
python .\run_chemar.py
```

Обычный запуск графиков не сохраняет изображения. PNG создаются только по команде:

```powershell
python .\run_chemar.py --save-only
```

## 3. Общая последовательность работы

```text
species.json ──────┐
reactions.json ────┼──> проверка входных данных
calculation.json ──┘              │
                                  v
                         начальное состояние смеси
                                  │
                                  v
                 термодинамика и скорости реакций
                                  │
                                  v
                  адаптивное интегрирование SDIRK
                                  │
                      ┌───────────┴───────────┐
                      v                       v
                results.csv             results.json
                                              │
                                              v
                                       run_chemar.py
                                              │
                                              v
                              температура / давление / состав
```

При запуске программа:

1. Загружает `species.json`.
2. Создаёт таблицу соответствия `название вещества → числовой индекс`.
3. Загружает `calculation.json` и проверяет начальный состав.
4. Загружает `reactions.json`, заменяя названия веществ числовыми индексами.
5. Проверяет сохранение каждого химического элемента и массы.
6. Переводит относительный начальный состав в моль/кг.
7. Рассчитывает начальное термодинамическое состояние.
8. Интегрирует систему кинетических уравнений.
9. После каждого заданного интервала записывает одну точку в CSV и JSON.

## 4. Требования

Для сборки C++ нужны:

- CMake версии 3.16 или новее;
- компилятор с поддержкой C++17;
- на Windows можно использовать MinGW-w64 GCC.

Библиотека `nlohmann/json` уже находится в `third_party`, поэтому интернет при сборке не нужен.

Python не требуется для самого расчёта. Он нужен только для:

- построения графиков через `run_chemar.py`;
- преобразования старых файлов через `convert_legacy_to_json.py`.

Для графиков требуется Matplotlib:

```powershell
python -m pip install matplotlib
```

.\build\chemar.exe --steps 100 --output .\test-output

```powershell
.\build\chemar.exe --diagnostics
```

## 7. Входные JSON-файлы

В одной входной папке обязательно должны находиться:

```text
calculation.json
species.json
reactions.json
```

Названия файлов фиксированы. Программа сначала читает вещества, затем начальные условия, затем реакции.

Все числа должны быть обычными конечными JSON-числами. Записи `NaN`, `Infinity` и комментарии стандарт JSON не допускает.

### Единицы измерения

| Величина | Единица |
| --- | --- |
| Температура | К |
| Давление | Па |
| Плотность | кг/м³ |
| Скорость | м/с |
| Молярная масса | кг/моль |
| Энтальпия вещества | Дж/моль |
| Теплоёмкость вещества | Дж/(моль·К) |
| Энтропия вещества | Дж/(моль·К) |
| Состав внутри решателя и результата | моль/кг |
| Время | с |
| Расстояние в режиме потока | м |

## 8. `calculation.json`

Этот файл содержит начальное состояние, режим моделирования и относительный состав смеси.

Пример:

```json
{
  "calculation": {
    "mode": "fixed_density_internal_energy",
    "velocity_m_s": 1.0,
    "density_kg_m3": 0.18,
    "pressure_pa": 101325.0,
    "temperature_k": 1100.0,
    "output_intervals": 10000,
    "output_interval": 1e-6,
    "use_tabulated_reverse_rates": false
  },
  "initial_composition": {
    "H2": 0.6667,
    "OH": 0.0,
    "H2O": 0.0,
    "O2": 0.3333,
    "H2O2": 0.0,
    "HO2": 0.0,
    "H": 0.0,
    "O": 0.0,
    "N2": 0.5
  }
}
```

### Поля раздела `calculation`

| Поле | Тип | Значение |
| --- | --- | --- |
| `mode` | строка | Режим моделирования |
| `velocity_m_s` | число | Начальная скорость; физически используется в режиме потока |
| `density_kg_m3` | число | Начальная плотность |
| `pressure_pa` | число | Начальное давление |
| `temperature_k` | число | Начальная температура, должна быть положительной |
| `output_intervals` | целое | Количество интервалов записи, может быть нулём |
| `output_interval` | число | Размер одного интервала записи, должен быть положительным |
| `use_tabulated_reverse_rates` | логическое | Способ вычисления обратных констант |

Все поля обязательны, даже если конкретный режим не использует одно из них для формирования начального состояния.

### Продолжительность расчёта

Для режимов 1–4:

```text
конечное время = output_intervals × output_interval
```

В контрольном примере:

```text
10000 × 1e-6 с = 0,01 с = 10 мс
```

В результате получается 10 001 точка: начальная точка плюс 10 000 завершённых интервалов.

Для режима `post_shock_flow` та же формула задаёт конечное расстояние в метрах.

### Начальный состав

`initial_composition` должен содержать каждое вещество из `species.json` ровно один раз. Неизвестные и пропущенные вещества считаются ошибкой.

Значения являются относительными молярными количествами, а не готовыми мольными долями и не моль/кг. Они могут иметь любой общий масштаб:

```json
{"A": 2, "B": 1}
```

эквивалентно смеси с тем же отношением:

```json
{"A": 20, "B": 10}
```

Программа вычисляет массу заданной относительной смеси:

```text
mass = Σ(relative_amount[i] × molar_mass[i])
```

и переводит состав в рабочие единицы:

```text
amount_mol_per_kg[i] = relative_amount[i] / mass
```

Все количества должны быть неотрицательными, а их сумма должна быть положительной.

## 9. Пять режимов моделирования

| `mode` | Постоянные величины | Какие начальные поля используются | Координата |
| --- | --- | --- | --- |
| `fixed_density_temperature` | Плотность и температура | `density_kg_m3`, `temperature_k` | время, с |
| `fixed_pressure_temperature` | Давление и температура | `pressure_pa`, `temperature_k` | время, с |
| `fixed_density_internal_energy` | Плотность и внутренняя энергия | `density_kg_m3`, `temperature_k` для начальной энергии | время, с |
| `fixed_pressure_enthalpy` | Давление и энтальпия | `pressure_pa`, `temperature_k` для начальной энтальпии | время, с |
| `post_shock_flow` | Потоки массы, импульса и полная энтальпия | `velocity_m_s`, `density_kg_m3`, `temperature_k` до скачка | расстояние, м |

### `fixed_density_temperature`

Плотность и температура не меняются. Давление пересчитывается по текущему составу:

```text
p = ρ × Rmix × T
```

Поле `pressure_pa` не задаёт фактическое начальное давление в этом режиме.

### `fixed_pressure_temperature`

Давление и температура постоянны. Плотность меняется вместе с составом:

```text
ρ = p / (Rmix × T)
```

### `fixed_density_internal_energy`

Плотность постоянна. После изменения состава температура подбирается методом Ньютона так, чтобы удельная внутренняя энергия оставалась равной начальному значению.

Это режим контрольного примера.

### `fixed_pressure_enthalpy`

Давление постоянно. Температура подбирается так, чтобы сохранялась удельная энтальпия. Затем пересчитывается плотность.

### `post_shock_flow`

`velocity_m_s`, `density_kg_m3` и `temperature_k` описывают сверхзвуковое состояние до нормального скачка уплотнения. Скорость должна превышать скорость звука.

Сначала программа находит состояние сразу после скачка. Затем вдоль реагирующего потока сохраняются:

```text
массовый поток:      ρu
поток импульса:      p + ρu²
полная энтальпия:    h + u²/2
```

В этом режиме `output_interval` измеряется в метрах, а производные состава вычисляются по расстоянию.

## 10. `species.json`

Файл описывает список химических элементов и все вещества механизма.

Упрощённый пример:

```json
{
  "elements": ["H", "O", "N"],
  "species": [
    {
      "id": 18,
      "name": "H2",
      "molar_mass_kg_mol": 0.0020158,
      "elements": {
        "H": 2
      },
      "thermodynamics": [
        {
          "minimum_temperature_k": 100.0,
          "maximum_temperature_k": 600.0,
          "reference_enthalpy_j_mol": -8468.0,
          "enthalpy_coefficients": [0, 0, 0, 0, 0, 0],
          "entropy_coefficients": [0, 0, 0, 0, 0, 0]
        }
      ]
    }
  ]
}
```

Нули в примере показывают только структуру. Для реального вещества должны использоваться корректные термодинамические коэффициенты.

### `elements`

Массив произвольных уникальных названий химических элементов. В C++ нет фиксированного списка или массива на 32 позиции.

Например, механизм может содержать:

```json
"elements": ["C", "H", "O", "N", "Ar"]
```

### Поля вещества

| Поле | Назначение |
| --- | --- |
| `id` | Положительный уникальный идентификатор |
| `name` | Непустое уникальное название вещества |
| `molar_mass_kg_mol` | Положительная молярная масса в кг/моль |
| `elements` | Объект `элемент: количество атомов` |
| `thermodynamics` | Один или несколько температурных интервалов |

Название `M` зарезервировано для универсального третьего тела и не может быть названием обычного вещества.

Элементы с нулевым количеством можно не записывать:

```json
"elements": {
  "H": 2,
  "O": 1
}
```

означает молекулу с двумя атомами H и одним атомом O.

### Температурные интервалы

Каждое вещество должно иметь хотя бы один термодинамический интервал. Интервалы должны идти по возрастанию температуры, соприкасаться или перекрываться и не иметь разрывов.

Для температуры внутри диапазона выбирается соответствующий полином. Если температура выходит за общий диапазон, энтальпия и энтропия продолжаются с теплоёмкостью на ближайшей границе.

### Термодинамические полиномы

Пусть:

```text
x = T / 10000
```

для температуры, ограниченной границами выбранного интервала.

Для массива:

```json
"enthalpy_coefficients": [a0, a1, a2, a3, a4, a5]
```

используются формулы:

```text
h(T)  = a0 + a1/x + a2×x + a3×x² + a4×x³ + a5×x⁴

cp(T) = (a2 - a1/x² + 2a3×x + 3a4×x² + 4a5×x³) × 1e-4
```

Для массива:

```json
"entropy_coefficients": [b0, b1, b2, b3, b4, b5]
```

используется:

```text
s(T) = b0 + b1×ln(x) + b2/x² + b3×x + b4×x² + b5×x³
```

Полученные `h`, `cp` и `s` относятся к одному молю вещества.

За пределами интервала при граничной температуре `Tb` применяется продолжение:

```text
h(T) = h(Tb) + cp(Tb) × (T - Tb)
s(T) = s(Tb) + cp(Tb) × ln(T / Tb)
```

`reference_enthalpy_j_mol` также используется в диагностической термодинамической таблице.

Не изменяйте эти коэффициенты без источника термодинамических данных: небольшая ошибка может существенно изменить равновесие и скорость реакции.

## 11. `reactions.json`

Файл содержит массив реакций:

```json
{
  "reactions": [
    {
      "reversible": true,
      "reactants": ["H2", "O2"],
      "products": ["OH", "OH"],
      "forward_rate": {
        "prefactor": 17000000.0,
        "temperature_exponent": 0.0,
        "activation_temperature_k": 24157.0
      },
      "reverse_rate": {
        "prefactor": 39217000.0,
        "temperature_exponent": 0.0,
        "activation_temperature_k": -5469.7
      }
    }
  ]
}
```

### Поля реакции

| Поле | Назначение |
| --- | --- |
| `reversible` | `true` для обратимой реакции, `false` для необратимой |
| `reactants` | Массив названий реагентов |
| `products` | Массив названий продуктов |
| `forward_rate` | Параметры прямой реакции |
| `reverse_rate` | Параметры обратной реакции; обязательны в описанном ниже режиме |

Обе стороны реакции должны быть непустыми. Все названия, кроме `M`, должны существовать в `species.json`.

### Стехиометрические коэффициенты

Коэффициент задаётся повторением названия:

```json
"reactants": ["H", "H", "M"],
"products": ["H2", "M"]
```

соответствует:

```text
2H + M → H2 + M
```

При чтении JSON программа объединяет повторения и сохраняет явный коэффициент `2`.

### Важное ограничение кинетического порядка

Текущий формат описывает элементарный закон действующих масс. Каждое повторение вещества одновременно:

- увеличивает его стехиометрический коэффициент;
- увеличивает его кинетический порядок на единицу.

Например, для `reactants: ["H", "H", "M"]` прямая скорость пропорциональна:

```text
[H]² × [M]
```

Формат пока не позволяет отдельно задать дробный или произвольный кинетический порядок. Для неэлементарного закона скорости потребуется расширение формата и модели.

### Третье тело `M`

Специальное название `M` означает суммарную молярную концентрацию смеси:

```text
[M] = Σ concentration[i]
```

`M` должно встречаться с одинаковой кратностью с обеих сторон, потому что оно не расходуется.

Конкретное вещество-катализатор, например `N2`, записывается своим обычным именем с обеих сторон. Тогда его концентрация входит в закон скорости, но чистое изменение количества равно нулю.

### Параметры Аррениуса

```json
{
  "prefactor": 17000000.0,
  "temperature_exponent": 0.0,
  "activation_temperature_k": 24157.0
}
```

При `T ≥ 300 К` используется:

```text
k(T) = A × Tⁿ × exp(-Ea/T)
```

где:

- `A` — `prefactor`;
- `n` — `temperature_exponent`;
- `Ea` — `activation_temperature_k`;
- `Ea` уже разделена на универсальную газовую постоянную и имеет размерность К.

`prefactor` должен быть неотрицательным. Показатель температуры и активационная температура могут быть отрицательными, если это предусмотрено механизмом.

Ниже 300 К сохраняется поведение исходной математической модели:

```text
k(T) = k(300 К) × T / 300 К
```

### Обратные реакции

Если в `calculation.json` указано:

```json
"use_tabulated_reverse_rates": true
```

то для каждой обратимой реакции обязателен объект `reverse_rate`. Обратная константа вычисляется по его параметрам Аррениуса.

Если указано `false`, заданные `reverse_rate` не используются в расчёте, а обратная константа выводится из термодинамического равновесия:

```text
ln(kr) = ln(kf)
       + Δν × ln(Ru × T / p°)
       + ΔG° / (Ru × T)
```

где:

```text
Δν  = сумма чистых стехиометрических коэффициентов
ΔG° = Σ ν[i] × (h[i] - T×s[i])
Ru  = 8,3144 Дж/(моль·К)
p°  = 101325 Па
```

Для необратимой реакции обратная скорость равна нулю.

### Проверка баланса

Для каждой реакции программа вычисляет чистый коэффициент каждого вещества и проверяет:

```text
Σ ν[i] × atom_count[i, element] = 0
```

отдельно для каждого элемента, а также:

```text
Σ ν[i] × molar_mass[i] ≈ 0
```

Несбалансированная реакция не допускается к расчёту.

## 12. Математическая модель смеси

Рабочий состав `n[i]` измеряется в моль/кг.

Удельная газовая постоянная смеси:

```text
Rmix = Ru × Σ n[i]
```

Молярная масса смеси:

```text
Mmix = Ru / Rmix = 1 / Σ n[i]
```

Молярная концентрация вещества:

```text
c[i] = ρ × max(0, n[i])
```

Термодинамические свойства смеси:

```text
h  = Σ n[i] × h[i]
cp = Σ n[i] × cp[i]
e  = h - p/ρ
γ  = cp / (cp - Rmix)
a  = sqrt(γ × p / ρ)
```

Энтропия учитывает парциальное давление каждого присутствующего вещества.

Для стороны реакции с кинетическими порядками `order[i]` скорость прогресса равна:

```text
q = k × Π c[i]^order[i]
```

Для `M` используется суммарная концентрация смеси.

Чистая скорость реакции:

```text
qnet = qforward - qreverse
```

В режимах времени производная состава имеет единицы моль/(кг·с):

```text
dn[i]/dt = Σ ν[i,reaction] × qnet / ρ
```

В режиме потока деление дополнительно выполняется на скорость газа, и получается производная по расстоянию:

```text
dn[i]/dx = Σ ν[i,reaction] × qnet / (ρu)
```

## 13. Численный метод

Химическая кинетика обычно создаёт жёсткую систему: быстрые и медленные реакции одновременно имеют сильно различающиеся временные масштабы. Поэтому программа использует неявный L-устойчивый SDIRK-метод второго порядка.

### SDIRK

Коэффициент диагонали:

```text
γ = 1 - 1/sqrt(2)
  = 0,2928932188134524756
```

Каждый шаг содержит две неявные стадии.

### Решение неявной стадии

Для каждой стадии решается нелинейное уравнение состава. Используется метод Ньютона:

1. Вычисляется невязка.
2. Матрица Якоби оценивается конечными разностями.
3. Линейная система решается методом Гаусса с выбором ведущего элемента.
4. Поправка Ньютона при необходимости уменьшается в 2 раза.
5. На одну стадию допускается до 12 итераций.

Если стадия не сходится или приводит к недопустимому состоянию, адаптивный алгоритм уменьшает шаг и повторяет попытку.

### Оценка ошибки

Для каждого шага программа сравнивает:

- один полный шаг;
- два последовательных полушага.

Для метода второго порядка ошибка двух полушагов оценивается как:

```text
error[i] = abs(refined[i] - full[i]) / (3 × scale[i])
```

где:

```text
scale[i] = atol + rtol × max(abs(start[i]), abs(refined[i]))
```

Используется максимальная ошибка по всем веществам.

Если ошибка не превышает 1, два полушага принимаются. Следующий размер шага увеличивается или уменьшается с ограничением коэффициента от `0,2` до `4,0`.

По умолчанию:

```text
rtol = 1e-9
atol = 1e-12 моль/кг
```

### Неотрицательность состава

Заметно отрицательное количество вещества отвергает неявную стадию. Небольшое отрицательное значение в пределах численного допуска округляется до нуля, после чего невязка проверяется повторно.

### Ошибка интегрирования

Если шаг приходится уменьшить ниже машинно допустимого размера или превышен бюджет попыток, программа:

- сохраняет все успешно рассчитанные точки;
- записывает в `results.json` поле `"completed": false`;
- добавляет текст ошибки;
- завершает работу с ненулевым кодом.

## 18. Проверка JSON и сообщения об ошибках

Программа проверяет:

- наличие всех трёх файлов;

Такой путь означает:

- файл `reactions.json`;
- первая реакция массива;
- первый элемент массива реагентов.

## 19. Добавление вещества или реакции

3. Укажите молярную массу в кг/моль.

4. Укажите `forward_rate`.
5. При необходимости укажите `reverse_rate`.
6. Запустите короткий расчёт с `--steps 1 --diagnostics`.
7. Проверьте баланс и диагностические константы.

## 22. Ограничения модели

- Газ считается идеальным.
- Вязкость, теплопроводность и диффузия не моделируются.
- Формат реакций описывает элементарный закон действующих масс.
- Отдельные произвольные кинетические порядки пока не задаются.
- Универсальное третье тело `M` имеет единичную эффективность для всех веществ.
- Индивидуальные эффективности третьих тел не поддерживаются.
- Точность физического результата зависит от качества термодинамических полиномов и параметров реакций.
- Численное совпадение с решением уравнений не является подтверждением экспериментальной точности механизма.

## 24. Типичные проблемы

### `chemar.exe` не найден

Соберите проект:

```powershell
cmake -S . -B build -G "MinGW Makefiles" -DCMAKE_CXX_COMPILER=g++ -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel
```

### `cannot open file`

Проверьте, что в папке, переданной через `--data`, есть все три файла с точными именами:

```text
calculation.json
species.json
reactions.json
```

### `unknown species`

Название в `calculation.json` или `reactions.json` не совпадает с `name` из `species.json`. Сравнение чувствительно к регистру: `H2` и `h2` — разные строки.

### `reaction does not conserve element`

Проверьте количество повторений реагентов и продуктов, а также атомный состав веществ.

### `required when use_tabulated_reverse_rates is true`

У обратимой реакции отсутствует `reverse_rate`. Добавьте его либо установите:

```json
"use_tabulated_reverse_rates": false
```

### `requires a supersonic upstream state`

Для `post_shock_flow` начальная скорость недостаточна для состояния перед нормальным скачком.

### `Adaptive integration failed`

Возможные причины:

- ошибочные параметры реакции;
- некорректные термодинамические данные;
- состояние вышло за физически допустимую область;
- слишком строгие допуски;
- чрезвычайно быстрые реакции относительно заданного масштаба.

Сначала запустите один интервал с `--diagnostics` и проверьте константы скоростей.

### Графики не открываются

Проверьте Python и Matplotlib:

```powershell
python --version
python -m pip show matplotlib
```
