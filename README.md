# CHEMAR: руководство пользователя и описание реализации

CHEMAR рассчитывает неравновесную химическую кинетику однородной газовой
смеси в нульмерном адиабатическом реакторе постоянной плотности.
Реализован режим IPR=3 исходной программы Fortran. Текущий механизм содержит
18 обратимых реакций из таблицы H2_O2_polnaya_tablitsa_bez_oformleniya.xlsx,
лист H2_O2, строки 2–19. Термобаза содержит девять веществ.

Документация описывает текущий C++17-проект после удаления проверочных
материалов. Рабочие входы — три YAML-файла. Результат расчёта — CSV.
Отдельный Python-скрипт показывает графики без сохранения изображений.

## 1. Быстрый запуск

Откройте PowerShell в каталоге проекта:

```powershell
cd C:\chem_kinetics
```

Если программа уже собрана:

```powershell
.\build-cpp17\chemar.exe
```

Результаты появятся в `output/results.csv`. Повторный запуск перезаписывает
этот файл. Параметры расчёта редактируются в `data/initial.yaml`;
после изменения YAML пересобирать программу не нужно.

Для просмотра результатов:

```powershell
python plot_results.py output/results.csv
```

Для выбора веществ:

```powershell
python plot_results.py output/results.csv --species H2 O2 OH H
```

Откроются три графика: температура, давление и концентрации.
PNG-файлы, каталог `plots` и `validation.log` программа не создаёт.

## 3. Сборка и зависимости

### 3.1. Что требуется

Для реактора нужны компилятор C++17, CMake не ниже 3.16 и yaml-cpp не ниже 0.8.
Приведённые команды используют Ninja, поэтому он также должен быть доступен.
Проверенная среда: Windows, GCC 13.2 и CMake 3.29.

Python нужен только для графиков. Скрипт использует стандартные модули
`argparse`, `csv`, `math`, `pathlib` и библиотеку matplotlib.
Fortran, PyYAML, pandas, Eigen и SUNDIALS для работы проекта не нужны.

### 3.2. Команды сборки

Из корня проекта:

```powershell
cmake -S . -B build-cpp17 -G Ninja -DCMAKE_CXX_COMPILER=g++ -DCMAKE_BUILD_TYPE=Release
cmake --build build-cpp17 -j 4
```

CMake сначала ищет установленный yaml-cpp. Если он не найден, загружается
версия 0.8.0 с GitHub с проверкой SHA256. Для этой загрузки нужна сеть.
При повторной сборке используется уже загруженная зависимость.

Если исходники yaml-cpp 0.8.0 заранее сохранены локально, их можно указать
при настройке сборки:

```powershell
cmake -S . -B build-cpp17 -G Ninja -DCMAKE_CXX_COMPILER=g++ -DCMAKE_BUILD_TYPE=Release -DFETCHCONTENT_SOURCE_DIR_YAML-CPP=C:/libraries/yaml-cpp-0.8.0
```

Путь `C:/libraries/yaml-cpp-0.8.0` — пример; замените его своим.

Для matplotlib:

```powershell
python -m pip install matplotlib
```

На Linux аналогичная сборка возможна теми же командами CMake при наличии GCC
и Ninja; запуск исполняемого файла: `./build-cpp17/chemar`.
Проверка текущей версии проекта выполнялась на Windows.

### 3.3. Когда пересобирать

После изменения `.cpp`, `.hpp` или CMake выполните сборку заново.
Изменение YAML или Python-скрипта не требует пересборки C++.
Если меняется компилятор или генератор CMake, используйте новый каталог сборки.

## 4. Запуск и пути к файлам

Реактор принимает не более одного аргумента — каталог с входными YAML:

```powershell
.\build-cpp17\chemar.exe
.\build-cpp17\chemar.exe data
.\build-cpp17\chemar.exe "C:\my_calculations\case1"
```

Без аргумента используется `data` относительно текущего рабочего каталога.
В выбранном каталоге должны находиться все три файла с точными именами:
`initial.yaml`, `species.yaml`, `reactions.yaml`.

Путь `output.csv` внутри YAML тоже считается относительно рабочего каталога,
а не относительно `initial.yaml` и не относительно исполняемого файла.
Поэтому удобнее запускать программу из корня проекта.

Коды завершения реактора:

| Код | Значение |
|---|---|
| 0 | Расчёт успешно завершён |
| 1 | Ошибка данных, вычислений или файлового ввода-вывода |
| 2 | Передано слишком много аргументов командной строки |

## 5. Начальные данные: initial.yaml

Полный поставляемый файл:

```yaml
mode: constant_density_energy
temperature_K: 1100.0
density_kg_m3: 0.18
mole_fractions:
  H2: 0.6667
  O2: 0.3333
  N2: 0.5
time_end_s: 0.01
reverse_rates: thermodynamic
solver:
  theta: 0.6
  initial_step_s: 1.0e-08
  min_step_s: 1.0e-18
  max_step_s: 1.0e-06
  relative_tolerance: 1.0e-06
  absolute_tolerance_mol_m3: 1.0e-11
  nonlinear_tolerance: 1.0e-05
  max_newton_iterations: 30
  max_steps: 2000000
output:
  csv: output/results.csv
  save_every: 10
```

Используйте пробелы для отступов YAML и точку как десятичный разделитель.
Приведённые поля считываются явно: начальные значения в C++-структуре Settings
не делают соответствующие поля YAML необязательными.

### 5.1. Физические параметры

| Поле | Смысл и ограничения |
|---|---|
| `mode` | Только `constant_density_energy` |
| `temperature_K` | Начальная температура, K, в общем термодиапазоне механизма |
| `density_kg_m3` | Положительная постоянная плотность, kg/m³ |
| `mole_fractions` | Неотрицательные относительные молярные количества; хотя бы одно положительное |
| `time_end_s` | Положительное конечное время, s; начальное время всегда 0 |
| `reverse_rates` | `thermodynamic` или `explicit` |

Названия веществ чувствительны к регистру и должны совпадать с `species.yaml`.
Неуказанные вещества получают нулевую начальную концентрацию.
Отрицательные количества и неизвестные названия приводят к ошибке.

### 5.2. Нормировка состава

Значения `mole_fractions` могут быть заданы в любых одинаковых молярных
пропорциях. Если введены q_i, их нормированные доли равны:

$$
x_i = \frac{q_i}{\sum_k q_k}.
$$

Начальные концентрации программа вычисляет непосредственно по формуле:

$$
c_{i,0} = \frac{\rho q_i}{\sum_k q_k M_k}.
$$

M_i — молярная масса в kg/mol, c_i — концентрация в mol/m³.
Так автоматически выполняется равенство суммы c_i M_i заданной плотности.

Например, заменив только блок состава на следующий, можно задать H2:O2=2:1
без азота:

```yaml
mole_fractions:
  H2: 2.0
  O2: 1.0
```

Это другой расчёт по сравнению с поставляемой смесью с N2. В текущем механизме
M обозначает всю смесь: исключение N2 меняет концентрации и теплоёмкость,
но само по себе не обнуляет реакции с третьим телом.

### 5.3. Начальные давление и энергия

Они не являются независимыми входами режима IPR=3:

$$
p_0 = R T_0 \sum_i c_{i,0},
\qquad
E_0 = \sum_i c_{i,0} u_i(T_0).
$$

Для поставляемого состава после нормировки:

| Вещество | Молярная доля | Концентрация, mol/m³ |
|---|---:|---:|
| H2 | 0.4444666666667 | 4.612806203379089 |
| O2 | 0.2222 | 2.306057158521449 |
| N2 | 0.3333333333333 | 3.459431680950269 |

Остальные концентрации равны нулю. Начальное давление — 94918.2259347 Pa.

### 5.4. Численные параметры

| Поле в `solver` | Смысл |
|---|---|
| `theta` | Вес нового источника; допускается от 0.5 до 1 включительно |
| `initial_step_s` | Первый пробуемый внешний шаг |
| `min_step_s` | Нижняя граница уменьшения шага при неудаче |
| `max_step_s` | Верхняя граница внешнего шага |
| `relative_tolerance` | Положительный относительный масштаб ошибки |
| `absolute_tolerance_mol_m3` | Положительный абсолютный масштаб ошибки концентраций |
| `nonlinear_tolerance` | Порог нормированной невязки химического Ньютона: больше 0 и меньше 0.01 |
| `max_newton_iterations` | Число итераций химического Ньютона, целое от 1 до 1000 |
| `max_steps` | Положительный целый предел числа попыток внешнего шага, включая отклонённые |

Должно выполняться:

```text
0 < min_step_s <= initial_step_s <= max_step_s
```

Эти параметры управляют численной точностью и сходимостью, а не физикой.
Сохранение результатов регулируется отдельно: `save_every` не задаёт шаг
интегрирования и не гарантирует равномерные интервалы строк CSV.

### 5.5. Выходные параметры

| Поле в `output` | Смысл |
|---|---|
| `csv` | Непустой путь к CSV; отсутствующие родительские каталоги создаются |
| `save_every` | Положительное целое: сохранять каждый N-й принятый внешний шаг |

При `save_every: 1` сохраняется каждый принятый внешний шаг.
Начальное и конечное состояния сохраняются при любом значении save_every.

## 6. Термоданные: species.yaml

Корневые поля:

```yaml
model: Glushko_Gurvich
species:
```

Этот фрагмент показывает структуру и не заменяет полный файл.
Поддерживается только модель `Glushko_Gurvich`.

Каждая запись вещества содержит:

| Поле | Содержимое |
|---|---|
| `name` | Уникальное непустое имя без запятых, кавычек и переводов строки |
| `molar_mass_kg_mol` | Положительная молярная масса в kg/mol |
| `atoms` | Словарь «элемент: положительное целое количество атомов» |
| `thermo` | Непустой упорядоченный список температурных интервалов |
| `legacy_id` | Справочный идентификатор исходных данных; загрузчик его не использует |

Каждый интервал содержит `T_min`, `T_max` и `coefficients` — ровно 12 конечных
чисел. Должно быть 0 < T_min < T_max. Интервалы записываются по возрастанию,
границы соседних интервалов должны совпадать. На общей границе выбираются
коэффициенты нижнего интервала.

Общий разрешённый диапазон — пересечение диапазонов всех загруженных веществ,
даже если некоторые из них имеют нулевую концентрацию. У поставляемых данных
это 500–6000 K. Продолжение термоданных за границы не выполняется.

Порядок записей определяет индексы во всех векторах и порядок концентрационных
столбцов CSV. Текущий порядок: H2, OH, H2O, O2, H2O2, HO2, H, O, N2.

### 6.1. Формулы термодинамики

В формулах ниже b[0]…b[11] — значения массива coefficients в порядке YAML,
x = T/10000, а нумерация начинается с нуля, как в C++.
Первые четыре параметра уже перенесены в J/mol; повторно умножать их на 1000
при редактировании готового YAML не нужно. Остальные параметры подставляются
в следующие формулы в сохранённой нормировке исходной модели:

$$
\begin{aligned}
h(T) ={}& b_2-b_3-10^4 b_7-2\cdot10^4 b_6/x \\
        &+10^4 b_5x+10^4 b_8x^2+2\cdot10^4 b_9x^3+3\cdot10^4 b_{10}x^4,\\
s(T) ={}& b_4+b_5+b_5\ln x-b_6/x^2+2b_8x+3b_9x^2+4b_{10}x^3,\\
C_p(T) ={}& b_5+2b_6/x^2+2b_8x+6b_9x^2+12b_{10}x^3.
\end{aligned}
$$

Далее вычисляются:

$$
C_v=C_p-R,\qquad u=h-RT,\qquad g=h-Ts.
$$

h, u и g имеют единицы J/mol; Cp, Cv и s — J/(mol·K).
В коде дополнительно требуется Cp > R, то есть положительная Cv.
Параметры b[0], b[1], b[11] сохранены из исходной записи, но в этих формулах
не участвуют. Используется модель Глушко/Гурвича, а не NASA7.

## 7. Реакции: reactions.yaml

Источник — H2_O2_polnaya_tablitsa_bez_oformleniya.xlsx, лист H2_O2, A1:L19.
Механизм полностью заменяет прежние семь реакций. Порядок и направления
соответствуют столбцу «Прямая реакция»; все 18 реакций обратимы.

Корневой маркер единиц — `units: SI_mol_m_s_K`. Поля source_file и source_sheet
сохраняют происхождение данных и не участвуют в вычислениях.
Пример первой записи внутри списка reactions:

```yaml
- id: 1
  reactants:
    H: 1
    O2: 1
  products:
    OH: 1
    O: 1
  reversible: true
  forward:
    A: 120000000000.0
    n: -0.91
    activation_temperature_K: 8311.0
  fit_range_K: [300.0, 2500.0]
  reference:
    temperature_K: 1000.0
    forward_rate_constant: 54923.70261003257
    equilibrium_constant: 0.003992087024388099
    reverse_rate_constant: 13758142.614251047
```

Реагенты и продукты — словари с положительными целыми коэффициентами.
Имена должны присутствовать в species.yaml; обе стороны должны быть непустыми.
Дробные коэффициенты и независимые от стехиометрии порядки не поддерживаются.

forward обязателен. A неотрицательно; n и температура активации могут иметь
любой конечный знак. Поля id, fit_range_K и reference — справочные:
загрузчик их не использует для выбора скорости или ограничения температуры.
В reference сохранены контрольные столбцы I–L Excel, а не постоянные
для подстановки на всех температурах.

В книге отсутствуют единицы A. Числа перенесены без дополнительного множителя
и трактуются в согласованной системе mol–m³–s–K. Это воспроизводит все
контрольные прямые константы из столбца J до округления; концентрационные Kc
для реакций с изменением числа молей также близки к расчёту в mol/m³.
Отдельного первичного источника размерностей книга не содержит.

Для обратного направления в книге даны уравнение реакции и k при одной T,
но нет отдельных троек AB, nB, EB/R. Поэтому используется
`reverse_rates: thermodynamic`, kr(T)=kf(T)/Kc(T). Блок reverse не выдумывается
по одной контрольной точке. Если переключить поставляемые данные на explicit,
загрузчик сообщит об отсутствии обратных параметров. Сам код поддерживает
explicit, когда такие параметры действительно заданы.
При reversible: false обратная скорость равна нулю.

| 5 | H₂ + M → 2H + M | 220000000 | 0 | 48349 | 2500–8000 |
| 6 | H + OH + M → H₂O + M | 140000000000 | -2 | 0 | 1000–3000 |
| 7 | O₂ + M → 2O + M | 120000000 | 0 | 54243 | 2000–10000 |
| 8 | H + O₂ + M → HO₂ + M | 700000 | -0.8 | 0 | 300–2000 |
| 9 | H + HO₂ → 2OH | 150000000 | 0 | 505 | 300–1000 |
| 10 | H + HO₂ → H₂ + O₂ | 25000000 | 0 | 349 | 300–1000 |
| 11 | O + HO₂ → OH + O₂ | 20000000 | 0 | 0 | 300–1000 |
| 12 | OH + HO₂ → H₂O + O₂ | 20000000 | 0 | 0 | 300–2000 |
| 13 | 2HO₂ → H₂O₂ + O₂ | 2000000 | 0 | 0 | 300–1200 |

| 15 | H + H₂O₂ → H₂ + HO₂ | 1700000 | 0 | 1888 | 300–800 |
| 16 | H + H₂O₂ → H₂O + OH | 10000000 | 0 | 1804 | 300–1000 |
| 17 | O + H₂O₂ → OH + HO₂ | 28000000 | 0 | 3223 | 300–1000 |
| 18 | OH + H₂O₂ → H₂O + HO₂ | 7000000 | 0 | 722 | 300–1000 |

HO2 и H2O2 теперь образуются и расходуются. N2 химически инертен,
но влияет на теплоёмкость и эффективную концентрацию третьего тела.

### 7.2. Третье тело

У реакций 5, 6, 7, 8 и 14 записано:

```yaml
third_body:
  default_efficiency: 1.0
  efficiencies: {}
```

Общая эффективная концентрация:

$$
[M]=\sum_i\varepsilon_i c_i.
$$

В книге нет специальных эффективностей. Принято стандартное для такой записи
M толкование: все эффективности равны 1, то есть [M]=сумме концентраций
всех девяти веществ. Специальная модель falloff/Troe не задана и не добавляется.

default_efficiency назначается всем веществам; словарь efficiencies при наличии
переопределяет отдельные значения. Все эффективности неотрицательны.
Без блока third_body множитель равен единице. M не является веществом:
его нет в species.yaml и в чистой стехиометрии, масса и атомы не меняются
от столкновения. Оба направления умножаются на одну и ту же [M].

Для реакции 6:

$$
w=[M]\left(k_f c_{OH}c_H-k_r c_{H2O}\right).
$$

В C++ проверены все 18 строк при температурах столбца I. Максимальное
относительное отличие kf от столбца J — 3.34e−15. Для Kc и kr максимальные
отличия от K и L составляют 0.171677% и 0.171383% соответственно,

Таблица не содержит термоданных, из которых получен её Kc. Текущая модель

Постоянная подстановка Kc из одной температуры нарушила бы температурную

## 8. Математическая модель и единицы

Реактор считается однородным: пространственных координат, диффузии,
теплопроводности, подвода тепла и потоков вещества через границу в модели нет.
Для закрытого реактора постоянной плотности объём также постоянен.
Смесь описывается уравнением идеального газа.

$$
\frac{dc_i}{dt}=\sum_j\nu_{ij}w_j,\qquad
\sum_i c_i u_i(T)=E_0,\qquad
p=RT\sum_i c_i.
$$

Здесь ν_ij = β_ij − α_ij; α и β — коэффициенты реагентов и продуктов.

| Величина | Единицы |
|---|---|
| Время t | s |
| Температура T | K |
| Давление p | Pa |
| Плотность ρ | kg/m³ |
| Концентрация c_i | mol/m³ |
| Молярная масса M_i | kg/mol |
| Молярная внутренняя энергия u_i, энтальпия h_i | J/mol |
| Cp_i, Cv_i, энтропия s_i | J/(mol·K) |
| Объёмная внутренняя энергия E0 | J/m³ |
| Скорость реакции w_j, источник dc_i/dt | mol/(m³·s) |

Используются R = 8.3144 J/(mol·K) и p° = 101325 Pa, как в исходнике.
Функция `energy()` возвращает объёмную энергию. Переменная e0 в solver.cpp
также содержит J/m³, несмотря на короткое имя. Для удельной энергии на массу
выполняется e0_specific = E0/ρ.

Энергия образования веществ включена в h и u. Поэтому превращение веществ
меняет температуру при неизменной сумме c_i u_i. Отдельный эмпирический
источник тепла в уравнение температуры не добавляется.

### 8.1. Закон Аррениуса

При T ≥ 300 K:

$$
k(T)=A T^n\exp(-T_a/T),\qquad T_a=E_a/R.
$$

Параметр activation_temperature_K — температура активации, а не энергия
в J/mol. Если исходно известна энергия, её сначала нужно разделить на R.
В реализации экспонента вычисляется как exp(ln A + n ln T − Ta/T).
При A=0 константа равна нулю.

Для направления полного порядка m, включая третье тело:

$$
[k]=(\mathrm{m^3/mol})^{m-1}/\mathrm{s},\qquad
[A]=(\mathrm{m^3/mol})^{m-1}\mathrm{s^{-1}K^{-n}}.
$$

| Порядок | Единицы k |
|---|---|
| 1 | s⁻¹ |
| 2 | m³/(mol·s) |
| 3 | m⁶/(mol²·s) |

Порядки прямого и обратного направлений могут отличаться. У реакции 6 прямой
порядок равен 3, обратный — 2. Для explicit размерности соответствующих A
должны различаться таким же образом.

Загрузчик не конвертирует cm³, kmol или калории. В готовых YAML должны быть
согласованные SI-параметры. В поставляемых данных повторные множители
1e−6 или 1e−12 не применяются: это изменило бы активную модель исходника.

Из Fortran сохранено продолжение k(T)=k(300)·T/300 при T<300 K. Для текущей
термобазы эта ветвь не используется, поскольку общий нижний предел — 500 K.

### 8.2. Прямые и обратные скорости

Без третьего тела:

$$
w_f=k_f\prod_i c_i^{\alpha_i},\qquad
w_r=k_r\prod_i c_i^{\beta_i},\qquad w=w_f-w_r.
$$

При наличии третьего тела оба направления дополнительно умножаются на [M].
Источник вещества получается суммированием ν_ij·w_j по реакциям.
Например, для H2+O2↔2OH вклад равен −w для H2 и O2 и +2w для OH.

В режиме thermodynamic используются:

$$
\Delta g=\sum_i\nu_i(h_i-Ts_i),\qquad \Delta\nu=\sum_i\nu_i,
$$

$$
\ln K_c=-\frac{\Delta g}{RT}+\Delta\nu\ln\frac{p^\circ}{RT},
\qquad k_r=\frac{k_f}{K_c}.
$$

Kc здесь понимается как численное значение концентрационной константы
при записи концентраций в mol/m³. При изменении общего числа молей
множитель p°/(RT) необходим для согласования размерностей направлений.
Нейтральный столкновитель в Δg и Δν не входит.

В режиме explicit обратная константа вычисляется по собственной тройке
Аррениуса. Такая аппроксимация не обязана точно согласовываться с равновесием
из термоданных. Выбор режима способен изменить результат расчёта.

## 9. Восстановление температуры

При заданных концентрациях решается одно уравнение:

$$
F(T)=\sum_i c_i u_i(T)-E_0=0,
\qquad F'(T)=\sum_i c_iC_{v,i}(T).
$$

Порядок действий функции temperature():

1. Проверить, что значения F на концах общего термодиапазона допускают корень.
2. Взять начальное приближение из предыдущей температуры внутри диапазона.
3. Вычислить невязку энергии и объёмную теплоёмкость.
4. Выполнить поправку Ньютона −F/F′, ограниченную по модулю 100 K.
5. Если новая точка выходит из текущего интервала поиска, взять его середину.
6. Повторять до сходимости, не более 150 итераций.

Критерий останова в численных SI-значениях:

```text
abs(F) <= 1e-14 * max(1, abs(E0))
```

Порог и число итераций этого скалярного решения находятся в chemistry.cpp.
Параметр max_newton_iterations из YAML относится к химической системе,
а не к этому восстановлению температуры.

Предписанная E0 в течение расчёта не обновляется. Несходимость температуры
во время попытки интегрирования приводит к её отклонению и уменьшению шага.

## 10. Интегрирование по времени

### 10.1. Взвешенная неявная схема

Если f(c) — химический источник с T, восстановленной из энергии, то:

$$
c_{n+1}=c_n+\Delta t[(1-\theta)f(c_n)+\theta f(c_{n+1})].
$$

При theta=0.6 веса равны 0.4 для старого источника и 0.6 для нового.
Это форма схемы исходного Fortran. При таком theta порядок точности первый.
При theta=0.5 получается трапецеидальная схема второго порядка для достаточно
гладкой задачи; при theta=1 — неявный Эйлер.

Одна A-устойчивость схемы не гарантирует положительности химического состава
при любом шаге. При theta<1 схема также не является L-устойчивой.
Поэтому сохраняются проверки допустимости и адаптивный выбор шага.

### 10.2. Химический метод Ньютона

Функция implicit_step() решает систему с невязкой:

$$
r(c)=c-c_n-\Delta t[(1-\theta)f(c_n)+\theta f(c)].
$$

На каждой итерации температура определяется из энергии. Затем строится
аналитический якобиан и решается система для поправки:

$$
[I-\theta\Delta t J_f]\,\delta c=-r.
$$

Производные учитывают как непосредственную зависимость скоростей от состава,
так и изменение температуры при постоянной энергии:

$$
\frac{\partial T}{\partial c_i}
=-\frac{u_i}{\sum_k c_k C_{v,k}},\qquad
\frac{d\ln K_c}{dT}=\frac{\Delta u}{RT^2}.
$$

Линейная система решается методом Гаусса с выбором ведущего элемента по столбцу.
Для текущих девяти веществ её матрица имеет размер 9×9. Плотная матрица здесь
относится только к решению Ньютона; стехиометрия хранится разреженно.

Поправка применяется с коэффициентом демпфирования λ. Сначала λ=1,
при неудаче он делится на 2; проверяется не более 45 вариантов.
Пробное состояние должно иметь конечные неотрицательные концентрации,
допустимую температуру и достаточно меньшую нормированную невязку:

```text
after < before * (1 - 1e-4 * lambda)
```

Концентрации не обрезаются до нуля и не перенормируются после шага.

Сходимость химического Ньютона проверяется по максимуму:

$$
\max_i\frac{|r_i|}{\mathrm{atol}
+\mathrm{rtol}\max(c_{n,i},c_i)}
\leq\mathrm{nonlinear\_tolerance}.
$$

### 10.3. Контроль ошибки шага

Для каждой внешней попытки рассчитываются один полный шаг Δt и два
последовательных половинных шага Δt/2. В качестве нового состояния принимается
результат двух половинных шагов. Экстраполяция не применяется.

Оценка ошибки — максимум по концентрациям и температуре:

$$
\epsilon=\max\left(
\max_i\frac{|c_i^{half}-c_i^{full}|}
{\mathrm{atol}+\mathrm{rtol}\max(c_{n,i},c_i^{half})},
\frac{|T^{half}-T^{full}|}{\mathrm{rtol}\,T^{half}}
\right).
$$

Здесь half обозначает конечный результат двух половинных шагов.
Если ε>1 либо неявное решение завершилось ошибкой, внешняя попытка
отклоняется, её время не засчитывается, а Δt делится на 2.
При выходе ниже min_step_s программа сообщает причину и прекращает расчёт.

После успеха следующий шаг определяется по формуле:

```text
factor = clamp(0.85 / sqrt(max(error, 1e-8)), 0.5, 1.5)
next_dt = min(max_step_s, dt * factor)
```

Последний шаг укорачивается до конечного времени; если короткий остаток
успешно решается, он может быть меньше min_step_s. Проверяется, что прибавление
шага действительно меняет число времени в арифметике double.

Один принятый внешний шаг включает два половинных шага и увеличивает
счётчик accepted на единицу. Счётчик rejected учитывает отклонённые попытки.
Три пробных вызова implicit_step() не считаются тремя принятыми шагами.

### 10.4. Как понимать допуски

При большой концентрации основной масштаб задаёт rtol·c, при близкой к нулю —
atol. Поэтому atol предотвращает деление на нуль и чрезмерные требования
к исчезающим компонентам. Для температуры используется относительный масштаб.

Это контроль локальной ошибки и невязки. Он не является гарантией такого же
относительного отклонения всей траектории от точного решения.
Для оценки точности полезно повторить расчёт с более строгими допусками
и меньшим максимальным шагом, сохраняя результаты под разными именами CSV.

## 11. Контроль сохранения

Перед расчётом prepare() проверяет атомный баланс каждой реакции:

$$
\sum_i\nu_{ij}a_{i,e}=0
$$

для каждого элемента e, где a_i,e — число атомов элемента в молекуле.
Также проверяется согласованность баланса молярных масс; допустимый остаток
по массе реакции — 1e−12 от суммы абсолютных вкладов.

После каждого принятого внешнего шага вычисляются:

$$
\rho_{calc}=\sum_i c_iM_i,\qquad
E_{calc}=\sum_i c_i u_i(T),\qquad
A_e=\sum_i a_{i,e}c_i.
$$

В консоли выводятся максимумы следующих ошибок за расчёт:

```text
mass_error   = abs(rho_calc / rho_initial - 1)
energy_error = abs(E_calc - E0) / max(1, abs(E0))
atom_error   = max_e abs(A_e - A_e0) / max(1, A_e0)
```

Все величины подставляются в численных SI-значениях. Для малых начальных
энергий или атомных концентраций последние две метрики являются нормированными
абсолютными ошибками, а не чисто относительными.

Расчёт останавливается, если максимальная ошибка массы или атомов превышает
1e−8, а энергии — 1e−9. Эти пороги находятся в solver.cpp и не задаются YAML.
Малая ошибка инвариантов сама по себе не доказывает точность момента воспламенения.

## 12. Формат результатов CSV

Постоянные первые столбцы:

| Столбец | Содержимое |
|---|---|
| `time_s` | Время, s |
| `temperature_K` | Температура, K |
| `pressure_Pa` | Давление, Pa |
| `density_kg_m3` | Постоянная заданная плотность, kg/m³ |
| `c_<имя>_mol_m3` | Концентрация соответствующего вещества, mol/m³ |

Концентрационные столбцы автоматически добавляются для всех записей
species.yaml в их порядке. Сейчас всего 13 столбцов: четыре общих и девять
концентрационных. Разделитель — запятая, десятичный разделитель — точка.
Файл содержит один заголовок, числа записываются с setprecision(17).

Запись выполняется последовательно через std::ofstream; вся история в памяти
C++ не накапливается. Начальная строка записывается сразу. Далее сохраняются
выбранные принятые шаги и обязательно конечное состояние без дублирования
последней строки. Время строк строго возрастает, но интервалы могут отличаться.

При N принятых шагах и save_every=S успешный расчёт содержит:

```text
1 + floor(N / S) + дополнительная конечная строка, если N не кратно S
```

Это число строк данных без заголовка. В поставляемом расчёте
N=15066, S=10: 1508 строк данных и один заголовок.

Программа проверяет открытие потока, запись строк и окончательное закрытие.
NaN, Inf и отрицательные концентрации не записываются как корректное состояние.

При вычислительной ошибке файл может содержать только начальную часть
траектории. При ошибке записи он может быть неполным. Открытие CSV выполняется
с перезаписью: не рассчитывайте сохранить предыдущие результаты при неудачном
новом запуске. Успех определяйте по коду завершения 0 и конечному времени.
Продолжение расчёта из существующего CSV не реализовано.

## 14. Устройство C++-кода

### 14.1. Структуры

| Структура | Основное содержимое |
|---|---|
| Term | Индекс вещества и целый стехиометрический коэффициент |
| ThermoInterval | Границы температуры и массив из 12 параметров |
| Species | Имя, молярная масса, атомный состав и интервалы термодинамики |
| Arrhenius | A, n и температура активации |
| Reaction | Реагенты, продукты, параметры направлений, обратимость, эффективности |
| Mechanism | Все вещества, реакции, чистая стехиометрия и общий термодиапазон |
| Thermo | cp, cv, h, s, u одного вещества |
| State | Время, температура, плотность и вектор c |
| RateConstants | Прямая и обратная константы, логарифм Kc |
| Rates | Прямые и обратные скорости реакций, источники и необязательный якобиан |
| Settings | Параметры численного решения |
| Input | Механизм, начальное состояние, настройки и путь вывода |
| Statistics | Счётчики шагов, максимумы ошибок и конечное состояние |

Давление не хранится в State: функция pressure() получает его из T и c.
В Rates поля forward/reverse содержат скорости в mol/(m³·s),
а в RateConstants одноимённые поля содержат константы соответствующих порядков.

Разреженная стехиометрия имеет тип vector<vector<Term>>:
внешний вектор — реакции, внутренний — только ненулевые ν_i этой реакции.
Реагенты и продукты хранятся отдельно для закона действующих масс.

### 14.2. Файлы и функции

| Файл | Функции и ответственность |
|---|---|
| main.cpp | Проверка аргументов, вызовы load/integrate, вывод статистики, обработка исключений |
| yaml_loader.cpp | load: чтение трёх файлов, проверка полей, индексы веществ, начальные концентрации |
| chemistry.cpp | prepare, thermo, arrhenius, rate_constants, rates, energy, mass, pressure, temperature |
| solver.cpp | implicit_step, linear_solve, integrate, csv_header, csv_row, atom_totals |
| chemistry.hpp | Структуры физической модели и объявления её функций |
| solver.hpp | Settings, Input, Statistics и объявления загрузки и решателя |

load() читает вещества, строит отображение имя→индекс, загружает реакции,
вызывает prepare(), затем читает начальные условия. В вычислительных циклах
используются индексы; повторный поиск вещества по имени не нужен.

prepare() строит чистую стехиометрию как β−α и проверяет механизм.
thermo() возвращает свойства вещества при T.
rate_constants() определяет kf, kr и ln Kc.
rates() суммирует источники и при запросе строит их аналитические производные.
product() — внутренняя функция для произведений концентраций и их производных;
она не делит на c_i, поэтому работает и при нулевых концентрациях.

integrate() управляет временем и внешними шагами, implicit_step() решает одну
дискретную нелинейную систему, а temperature() решает скалярный баланс энергии.
Это разные уровни итераций с разными критериями сходимости.

Обычный путь выполнения:

```text
main
  load
    чтение species.yaml и reactions.yaml
    prepare
    чтение initial.yaml
  integrate
    начальные энергия и CSV
    попытка полного и двух половинных шагов
      implicit_step
        temperature
        rates с якобианом
        linear_solve
        проверка демпфированной поправки
    контроль ошибки и принятие либо повтор шага
    проверка инвариантов и запись CSV
  вывод статистики
```

В коде используются обычные структуры и функции. Пространство имён chemar
удалено; тернарные операторы не используются, условия и циклы оформлены
отдельными блоками с фигурными скобками. Изменение файла данных не требует
изменения списка веществ в исходниках или функции записи CSV.

## 15. Диагностика ошибок

Сообщения реактора начинаются с CHEMAR:. Ошибки синтаксиса YAML также могут
содержать номер строки и столбца от yaml-cpp.

| Сообщение или группа | Что проверить |
|---|---|
| `bad file`, ошибка открытия YAML | Рабочий каталог, выбранный путь, наличие всех трёх файлов |
| `bad conversion`, `invalid node` | Обязательные ключи, типы значений и отступы YAML |
| `Реализован только режим IPR=3` | mode должен быть constant_density_energy |
| `Неизвестное вещество` | Имя вещества и его регистр в species.yaml |
| `Некорректный состав смеси`, `Некорректное начальное состояние` | Неотрицательный ненулевой состав и положительная плотность |
| `Начальная температура вне общего термодинамического диапазона` | Общий диапазон всех загруженных веществ |
| `Ожидалось 12 коэффициентов Гурвича` | Число параметров каждого интервала |
| `Некорректные термодинамические интервалы` | Порядок, положительность и совпадение соседних границ |
| `Реакция не сохраняет число атомов элемента ...`, `Реакция не сохраняет массу` | Баланс атомов и молярных масс реакции |
| `Не заданы параметры Аррениуса для обратной реакции` | Блок reverse у каждой обратимой реакции в режиме explicit |
| `Некорректные параметры интегрирования` | Диапазоны theta, шагов и допусков |
| `Решение уравнения энергии вне термодинамического диапазона` | Возможность удовлетворить энергетический баланс в допустимых T |
| `Некорректные термодинамические данные`, `Неположительная теплоёмкость...` | Коэффициенты, единицы, положительность Cv |
| `Переполнение при вычислении константы Аррениуса`, `Переполнение константы скорости обратной реакции`, `Переполнение скорости реакции` | Размерности A, величины коэффициентов, единицы температуры активации |
| `Вырожденная матрица метода Ньютона` | Вырожденность системы и корректность механизма; ошибка также может вызвать уменьшение шага |
| `Не удалось подобрать шаг метода Ньютона`, `Метод Ньютона для химической системы не сошёлся` | Допустимость состояния и достаточность шага/числа итераций |
| `Достигнут минимальный шаг при t=...` | Последнюю указанную причину; простое дальнейшее уменьшение min_step не исправляет модель |
| `Достигнут предел числа попыток шага` | max_steps и причину большого числа маленьких или отклонённых шагов |
| `Шаг слишком мал для увеличения времени при текущей точности вычислений` | Шаг стал слишком мал относительно текущего времени для double |
| `Проверка законов сохранения не пройдена` | Численную сходимость, данные и сделанные изменения формул |
| `Не удалось открыть CSV`, `Ошибка записи CSV`, `Ошибка закрытия или сброса буфера CSV` | Путь, права записи, свободное место и блокировку файла |

При проблемах сначала проверьте входные единицы и состав. Не изменяйте
одновременно много численных параметров: это затрудняет понимание причины.
Для трудного участка допустимо уменьшить начальный и максимальный шаги;
если это не помогает, изучите последнюю причину отказа.

При отсутствии графиков проверьте установку matplotlib и доступность
графического окружения. Если переменная окружения MPLBACKEND принудительно
выбирает неоконный backend, plt.show() не сможет показать обычные окна.
Ошибка `Choose distinct species from:` перечисляет допустимые имена из CSV.

## 16. Изменение расчёта и механизма

### 16.1. Другая температура, плотность или состав

Отредактируйте соответствующие поля initial.yaml и выполните реактор заново.
При сравнении вариантов задайте разные имена output.csv, чтобы не потерять
предыдущую траекторию. Начальное давление пересчитается автоматически.

### 16.2. Более подробная запись

Уменьшите save_every вплоть до 1. Это сохраняет больше строк, но не меняет
выбор шага и математическую точность интегрирования.

### 16.3. Новый набор условий в отдельном каталоге

Создайте каталог, скопируйте в него три YAML и измените нужные поля:

```powershell
New-Item -ItemType Directory -Force cases\case1
Copy-Item data\initial.yaml,data\species.yaml,data\reactions.yaml cases\case1
.\build-cpp17\chemar.exe cases\case1
```

Перед запуском задайте в новом initial.yaml свой путь CSV, если требуется
сохранить основной результат. Из корня проекта он всё равно разрешается
относительно корня, а не cases/case1.

### 16.4. Добавление вещества или реакции

Для нового вещества добавьте согласованные массу, атомы и термоданные во всех
нужных температурных интервалах. Для реакции добавьте стороны, прямую тройку,
признак обратимости, при необходимости обратную тройку и третье тело.
Все имена должны совпадать; атомный баланс проверяется автоматически.

Стехиометрия и новые столбцы CSV сформируются без изменения C++.
Однако проверка загрузки и атомного баланса не заменяет научной проверки
самих термоданных и кинетических параметров. При расширении механизма
нужно заново оценивать точность и устойчивость расчёта.

## 18. Отличия от исходного Fortran и ограничения

### 18.1. Решения о переносе данных

В исходном DHIM текстовый заголовок перечислял семь веществ, но программа
читала девять чисел по порядку термобазы. Поэтому сохранён фактически
прочитанный состав H2:O2:N2=0.6667:0.3333:0.5. Нули оставлены точными нулями;
искусственная примесь 1e−20, вводившаяся Fortran, не добавляется.

В термобазе объявлялись девять веществ. Дополнительная запись Ar за ними
исходной программой не читалась и в поставляемый YAML не включена.

В первоначальном механизме Fortran две реакции ошибочно помечались типом 7.
При первом переносе эти ошибки были исправлены. Текущий механизм полностью
заменён таблицей Excel: нумерация относится уже к её 18 строкам, а M означает
всю смесь. В C++ нет ветвления по старым типам реакций: всё задают списки сторон.

В Fortran были обнаружены чтение за границами массивов, проблемы загрузки
обратных параметров и обновления энергии/времени. В новой реализации энергия
фиксирована, отклонённые шаги не двигают время, а обратные параметры читаются
явно. Несходимость становится диагностируемым отказом попытки шага.

### 18.2. Какие режимы существуют

| IPR исходника | Постоянные величины или инварианты | Текущая поддержка |
|---|---|---|
| 1 | Плотность и температура | Не реализован |
| 2 | Давление и температура | Не реализован |
| 3 | Плотность и внутренняя энергия | Реализован как constant_density_energy |
| 4 | Давление и энтальпия | Не реализован |
| 5 | Поток массы, импульса и полной энергии стационарного течения | Не реализован |

Число IPR в YAML не указывается. Строка mode выбирает единственный
реализованный режим. Значение reverse_rates не является режимом реактора.

### 18.3. Область применимости

Общий термодиапазон поставляемой базы — 500–6000 K. Для каждой реакции
в Excel задан свой диапазон аппроксимации; они сохранены в fit_range_K.
Общего пересечения интервалов всех 18 реакций нет. Код не отключает реакции
вне этих интервалов и не обрезает температуру в формуле Аррениуса:
применяется экстраполяция, как и в первоначальном расчёте.
Наличие Tmax=8000 или 10000 K в отдельных строках не расширяет термобазу выше 6000 K.
Поэтому численная согласованность переноса не означает экспериментальной
точности всей траектории, особенно за пределами указанных диапазонов.

Не реализованы переменная плотность, внешнее тепло, пространственная структура,
диффузия, модели неидеального газа, falloff/Troe и произвольные порядки реакций.
Текущее третье тело — простой линейный множитель эффективной концентрации.

При значительно большем или более жёстком механизме малый плотный решатель
и выбранная взвешенная схема могут потребовать пересмотра. Результаты этого
примера не являются гарантией устойчивости и точности любого нового механизма.
